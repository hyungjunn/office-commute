# ADR 2. 배포 차단 이슈(Phase 0) 4건 해소 — /api 통일, 인터셉터 축소, Nginx 서빙, admin 비밀번호 로테이션

- 날짜: 2026-08-10
- 상태: 적용 완료 (근거 문서: docs/DEPLOYMENT.md §1, 커밋 4개로 분리 적용)

## 배경

2026-07-09 배포 전략 검증(docs/DEPLOYMENT.md)에서 "현재 코드 그대로는 어떤 방식으로도
배포가 동작하지 않는다"는 결론과 함께 차단 이슈 4건이 실증됐다:

1. **경로 충돌**: API 가 `/team`, `/commute` 등 루트에 흩어져 있어 SPA 라우트 `/overtime`이
   백엔드 `GET /overtime`과 정확히 충돌 — 새로고침/딥링크 시 페이지 대신 XML 에러.
2. **정적 자산 401**: `AuthInterceptor`가 `/**`에 걸려 있어 비로그인 상태에서 `/assets/*.js`가
   401 — 로그인 페이지 자체가 로드되지 않는다.
3. **SPA 서빙 주체 부재**: `frontend/dist`를 서빙하는 코드도 인프라도 없다.
4. **공개된 admin 비밀번호**: `V5__seed_admin.sql`이 평문 노출된 `admin1234`를 prod 에
   그대로 시드하고, 비밀번호 변경 수단이 없다.

각 이슈를 독립 커밋 하나로 해결해, 문제·수정·검증이 커밋 단위로 추적되게 했다.

## 결정과 구현

### 1. API 경로를 `/api/**`로 통일 (커밋 30c51f6)

컨트롤러 5개(Team/Employee/Commute/AnnualLeave/OverTime)에 클래스 레벨
`@RequestMapping("/api")`를 추가했다 — AuthController 의 기존 `/api/auth` 방식과 동일한
스타일이고, 메서드별 매핑은 건드리지 않아 diff 가 최소다.

Spec-first 원칙대로 `openapi.yml` 경로를 함께 갱신하고 `pnpm gen:api`로 `schema.d.ts`를
재생성했다. 이때 stale 상태였던 스펙 드리프트(ADR 1 의 휴일근로 필드 2개
`holidayWithin8HoursMinutes`/`holidayExceeding8HoursMinutes`가 schema.d.ts 에 없던 것)도
함께 해소됐다 — 배포 당일 체크리스트 1번이 미리 처리된 셈이다.

프론트는 openapi-fetch 가 경로 리터럴을 타입으로 검사하므로, 재생성 후 훅 5개와 엑셀
다운로드 경로를 `/api/*`로 바꾸면 tsc 가 누락을 잡아준다. vite 프록시는 경로 목록
유지보수 함정(`API_PATHS` 6개)에서 `/api` 단일 규칙으로 축소했다. 이후 모든 프록시
계층(vite dev, Nginx)의 규칙은 영원히 "`/api/**` → 백엔드, 나머지 → SPA" 한 줄이다.

`scripts/api_test.sh`도 같은 커밋에서 경로를 맞췄다.

### 2. `AuthInterceptor`를 `/api/**`에만 적용 (커밋 be5a4c9)

1번이 끝나야 가능한 수정이라 순서가 강제된다. 제외 목록 방식
(`/**` 적용 + `/`, `/error`, `/api/auth/**`, `/h2-console/**` 제외)을 적용 목록 방식
(`/api/**` 적용 + `/api/auth/**` 제외)으로 뒤집었다. 새 정적 자산·SPA 라우트가 생겨도
제외 목록을 따라다닐 필요가 없어진다. 죽은 예외였던 `/h2-console/**`(H2 콘솔 미사용)은
이때 제거했다.

구현 중 추가 발견: 미매핑 경로의 `NoResourceFoundException`을 전역 catch-all
(`@ExceptionHandler(Exception.class)`)이 삼켜 **500**으로 둔갑하고 있었다 — 문서의
"dev 에서 `/teams` 새로고침 시 백엔드 500 (실증됨)"의 근본 원인. 404 핸들러를 추가해
정정했다. 근거는 `WebConfigTest`가 고정한다: 비로그인 상태에서 비-API 경로는 404
(401 이 아님), `/api/**`는 여전히 401.

### 3. Nginx 가 SPA 를 서빙 (커밋 c67df36)

문서 §2 의 채택안대로 Spring static 서빙(단일 jar) 대신 Nginx 분리를 택했다.
선택 근거는 문서와 동일: 단일 jar 방식은 dist 복사 Gradle 태스크 + fallback 컨트롤러가
추가로 필요하고, 프론트만 고치는 배포에도 백엔드 재시작(=톰캣 인메모리 세션이라
전 직원 로그아웃)이 강제된다. Nginx 분리면 프론트 배포는 dist 교체 + reload 로 무중단.

추가된 파일:

- `deploy/nginx.conf` — TLS 종료, `/api/**` → `app:8080` 프록시(X-Forwarded-* 전달),
  나머지는 `try_files $uri /index.html` SPA fallback. 컨테이너에서 `nginx -t`로 문법 검증.
- `deploy/docker-compose.prod.yml` — nginx + app 2 서비스. 로컬 개발용 루트
  docker-compose.yml 과 별개 파일로 분리해 로컬 고정 비밀번호가 운영에 새지 않게 했다.
  DB 는 관리형 권장이라 mysql 서비스를 넣지 않았다. `docker compose config`로 검증.
- `Dockerfile` — CI 가 만든 bootJar 를 담는 eclipse-temurin:21-jre 런타임 이미지.
  `.dockerignore` 는 allowlist 방식(`*` 제외 후 `build/libs/*.jar`만 포함).
- `application-prod.yml` — `forward-headers-strategy: framework` + 세션 쿠키
  `Secure/HttpOnly/SameSite=Lax`. HTTPS 를 Nginx 가 종료하므로 X-Forwarded-* 를
  신뢰해야 쿠키 보안 판단이 올바르다 (§2 에서 미설정으로 확인됐던 부분).

### 4. admin 비밀번호 로테이션 (커밋 c01fefd)

문서는 `V7__rotate_admin_password.sql`로 예시했지만 그 사이 마이그레이션이 V10 까지
진행되어 **V11** 로 추가했다. 내용은 문서 그대로 Flyway placeholder 주입:

```sql
UPDATE employee SET password = '${admin_password_hash}' WHERE email = 'admin@company.com';
```

placeholder 값의 프로파일별 정책:

| 프로파일 | 값 | 근거 |
|---|---|---|
| prod | `${ADMIN_PASSWORD_HASH}` 기본값 없음 | 미설정 시 부팅 실패가 정상 — `DB_PASSWORD`와 같은 fail-fast 정책 |
| mysql (로컬 검증) | 기존 dev 해시가 기본값 | 로컬 로그인 흐름(admin1234) 유지, 환경변수로 덮어쓰기 가능 |
| test | 기존 dev 해시 고정 | Flyway 를 켜는 MySQL Testcontainers 테스트가 V11 에서 깨지지 않게 |

검증은 `AnnualLeaveServiceMySqlIntegrationTest`(Flyway 활성 + ddl-auto=validate)가
V1→V11 전체 체인 적용을 커버한다. dev 프로파일은 Flyway 자체가 꺼져 있어(data.sql 시드)
영향이 없다.

## 결과

- 배포 차단 4건이 모두 해소되어 docs/DEPLOYMENT.md §5 체크리스트를 진행할 수 있는
  상태가 됐다. 체크리스트 1번의 "schema.d.ts 재생성"도 1번 커밋에 포함됐다.
- 검증: 각 커밋마다 `./gradlew check`(Testcontainers 포함) + `pnpm build`(tsc) 통과.
  nginx/compose 는 각각 `nginx -t`, `docker compose config`로 정적 검증 — 실서버
  기동 검증(§5 체크리스트 3~9)은 배포 당일 항목으로 남는다.
- API 경로가 전부 `/api/**`가 되면서 프록시·인터셉터·프론트 훅이 같은 단일 규칙을
  공유한다. 새 컨트롤러는 `@RequestMapping("/api")`만 따르면 되고, 어기면
  `WebConfigTest` 방식의 401 테스트가 아니라 배포 후 라우팅에서 바로 드러난다 —
  스펙(openapi.yml)이 `/api` 외 경로를 갖지 않는 것이 1차 방어선이다.
- 미매핑 경로 응답이 500 → 404 로 바뀌었다. 에러 봉투(`NOT_FOUND`)는 유지.
- `admin1234`는 dev/로컬 전용이 됐다. 운영 배포 후 admin1234 로그인이 **실패**하는지
  확인하는 것이 체크리스트 4번이다.

## 남은 것 (이번 결정의 범위 밖)

- CI/CD 파이프라인 (§3) — GitHub Actions 워크플로는 아직 없다. `.github/`엔 이슈 템플릿뿐.
- 비밀번호 변경 API — V11 은 1회성 로테이션이고, placeholder 값 변경은 재실행되지
  않는다. 이후 로테이션 수단은 기존 리뷰 잔여 항목 E(중기 과제)와 동일.
- §6 개선 로드맵 전체 (로그인 실패 메시지 통일, rate limit, 401 전역 처리,
  actuator, XML 컨버터 제거, Spring Session 등) — 차단 아님.
- Vite 청크 500kB 경고 — 빌드는 통과하며 코드 스플리팅은 별도 과제.
