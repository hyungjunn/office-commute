# ADR 1. 초과근무 산정을 월 합계 상계에서 근로기준법 주 단위 산정으로 교체

- 날짜: 2026-08-09
- 상태: 적용 완료 (관련: TODO.md 5번 "법정 산정 방식 정합", 3번 일부 해소)

## 배경

초과근무 리포트는 급여 근거 자료다. 기존 구현은 **월 합계 상계** 방식이었다:

```
초과근무 = max(0, 월 근무 분 합계 − 소정근로시간)
소정근로시간 = (평일 수 − 평일 공휴일 수) × 8h        ← StandardWorkingTimeService
```

이 방식은 근로기준법 산정 방식이 아니다. 가산수당 대상 연장근로는 **1일 8시간 초과분과
1주 40시간 초과분**(제50조·제56조)이고, 서로 다른 날의 근무가 상계될 수 없다.

구체적 오류 세 가지:

1. **상계 오류**: 어떤 날 4h 야근하고 다른 날 4h 조퇴하면 월 합계는 0이지만,
   법적으로는 야근 4h의 가산수당(1.5배) 지급 의무가 남는다. → 임금 과소 지급.
2. **연차가 초과근무를 잡아먹는다** (TODO 3): 연차는 `workingMinutes=0`인데 소정근로시간은
   차감되지 않아, 연차 1일 쓴 직원은 8h 결손을 깔고 시작했다. 월 중 입사자도 같은 왜곡.
3. **가산율 뭉개짐**: 휴일근로(8h 이내 1.5 / 초과 2.0)와 연장근로가 단일 1.5로 뭉쳐 있어
   휴일 8h 초과 근무가 과소 지급됐다.

"조용히 틀린 값"이 "리포트가 안 나감"보다 비싸다는 이 저장소의 원칙상, 매월 1일 배치
발송(TODO 4)을 올리기 전에 산정 방식 자체를 바로잡아야 했다.

## 결정

### 산정 규칙 (2026-08-09 확정)

1주(월~일) 단위로 계산한다:

```
연장근로(1주) = Σ 일별 max(0, 실근로 − 8h)              ← 1일 8시간 초과분
             + max(0, Σ 일별 min(실근로, 8h) − 40h)     ← 주 40시간 초과 잔여분
```

두 항은 정의상 겹치지 않아 이중가산이 없다 (같은 시간이 일 초과이자 주 초과여도 한 번만).

정책 결정 네 가지 (모두 사용자 확인 완료):

| 결정 | 내용 | 근거 |
|---|---|---|
| 휴일근로 분리 | 일요일(주휴일)·공휴일 근무는 주 40h 산정 기반에서 **제외**하고 별도 트랙으로 집계, 8h 이내 1.5배 / 초과 2.0배. 토요일은 무급휴무일로 휴일이 아니며 주 40h 초과 경로로 잡힌다 | 제56조② (2018년 개정으로 휴일근로와 연장가산의 중복 배제 확정) |
| 연차는 실근로 기준 제외 | 연차 시간은 주 40h 산정에 넣지 않고 기준선도 40h 유지 | 연장근로 가산은 실근로시간 기준이 법정 원칙. 연차를 8h 근로로 간주하는 우대 정책은 채택하지 않음(필요 시 별도 결정) |
| 월 경계에 걸친 주 | 일별 초과분은 그 날이 속한 달, 주 40h 잔여분은 주가 끝나는 달에 귀속 | 위 식의 두 항이 분리 가능해 모든 시간이 정확히 한 번 집계된다. 매월 1일 배치 시점에 걸친 주는 아직 끝나지 않아 잔여분 이월은 데이터 가용성상으로도 강제되는 선택 |
| 주 시작 요일 = 월요일 | 1주 = 월~일 (ISO-8601) | 구현이 깔끔하고 주휴일(일요일)이 주의 끝에 온다. **취업규칙으로 정하는 사항이므로 규칙과 어긋나면 코드를 맞춰야 한다** |

### 구현

- **`MonthlyOverTimeCalculator` (신규, 순수 함수)**: 일별 근무 분 Map + 공휴일 Set → 월 귀속
  `MonthlyOverTime(연장, 휴일 8h 이내, 휴일 8h 초과)`. 산정 근거 사례는 전부
  `MonthlyOverTimeCalculatorTest`가 고정한다 (상계 불가, 주 6일×7h, 중복 가산 배제,
  토요일 경로, 연차 주간 야근, 월 경계 주 양쪽 달 검증 등).
- **`CommuteHistoryRepository`**: 월 SUM 쿼리(`findTotalWorkingMinutesByWorkDateBetween`)를
  일별 프로젝션 `findDailyWorkingMinutesByWorkDateBetween`으로 교체.
  `(employee_id, work_date)` unique 제약으로 하루 한 행, 연차·퇴근 미마감은 0분 행.
- **`OverTimeService`**: 조회 범위를 "대상 월 1일이 속한 주의 월요일 ~ 월 말일"로 확장
  (첫 주의 40h 판정에 전월 말 기록이 필요). 첫 주가 전월에 걸치면 전월 공휴일도 함께 조회
  — `HolidayApiClient` 직접 의존으로 변경.
- **출력 계층**: 응답·리포트 DTO에 `holidayWithin8HoursMinutes` / `holidayExceeding8HoursMinutes`
  추가, `openapi.yml` 동기화(Spec-first). 수당 = (연장 + 휴일 8h 이내) × 1.5 + 휴일 8h 초과 × 2.0,
  반올림은 합산 후 1회. 엑셀은 연장/휴일(이내·초과) 3개 시간 컬럼으로 확장.
- **퇴역**: `StandardWorkingTimeService`(소정근로일 개념)·`WeekendCalculator`·`TotalWorkingMinutes`
  및 테스트 삭제 — 월 소정근로시간이라는 기준선 자체가 사라졌다.

## 결과

- 상계 오류 소거: 조퇴가 야근을 지우지 못한다. 일별 초과 없이 주 총량만 넘는 경우(주 6일×7h)도 잡힌다.
- **TODO 3의 두 왜곡이 구조적으로 해소**: 소정근로시간 차감이 없으니 연차·월 중 입사가 결손을
  만들지 않는다. 연차 주간의 야근은 일 8h 초과로 그대로 집계된다(테스트 고정). 퇴사자 노출 문제만 남음.
- 휴일 8h 초과분이 2.0배로 정확히 지급된다.
- 공휴일 API 호출이 월 1회 → 최대 2회(전월 포함)로 늘었다. fail-closed 정책은 그대로 —
  실패 시 `HOLIDAY_DATA_UNAVAILABLE 503`, 배치에서는 재시도가 흡수(TODO 4).
- 리포트 수치의 의미가 바뀐다: 같은 데이터라도 기존 방식과 값이 다르다. 과거 월을 다시 조회하면
  새 방식으로 재계산되므로, 기존에 뽑아둔 리포트와의 차이는 산정 방식 변경으로 설명해야 한다.
- 월 경계 귀속 규칙상, 걸친 주의 주 40h 잔여분은 다음 달 리포트에 실린다 (급여 반영이 한 달 늦는
  것이 아니라, 그 주가 끝나야 확정되는 값이 확정되는 달에 실리는 것).
